### Blocking findings and independent reproductions

All examples below use public built `quota-matata` exports and resolved logging
config with `enabled:true`, a fresh directory under `/tmp/opencode`, and the
specified capture flag. Each reproduction calls `log`, awaits `close`, then
reads and JSON-parses the actual JSONL file. Marker values were found on disk,
not merely in an intermediate sanitizer result.

- **R11-01 [P1] — conversation/request exclusion is not recursive or universal.**
  `src/logging.ts:301-315,333-345,497-500` whitelists only the outer body
  envelope; its entire `error` subtree then enters `sanitizeValue(...,false)`.
  Unknown captured errors and plugin-owned errors also use that unrestricted
  walker. With capture enabled, a normal host-shaped provider error whose
  response body is
  `{"error":{"code":"BadRequest","prompt":"PROMPT_R11","messages":[{"content":"CONVERSATION_R11"}],"request":{"body":"REQUEST_R11"}}}`
  persists every marked field. An unknown provider error
  `{messages:[{content:"CONVERSATION_R11"}]}` also persists the conversation.
  Even with capture disabled, `plugin.error` with
  `{request:{body:"REQUEST_R11"}}` persists the request body.
  Required: enforce prompt/conversation/request-data exclusion independently
  of the free-text capture flag and event type; recursively reduce recognized
  error envelopes instead of admitting arbitrary nested objects. Add real-file
  regressions for nested envelopes, unknown objects and plugin error causes.
  This is an explicit no-request-data invariant, not a demand to recognize
  arbitrary prose as conversation content.

- **R11-02 [P1] — default withholding admits arbitrary provider free text.**
  `src/logging.ts:335-358` (walker at `221,276`) treats unknown array/string
  leaves as safe unless their property name hits a short blocklist.
  With capture disabled, `provider.error` with `error:["FREE_TEXT_R11"]`
  writes that free text. Unknown objects also preserve `description`,
  `details` string arrays and nested `request.data.input` text by default.
  Separately, a host-shaped error with body
  `{"code":"FREE TEXT FROM PROVIDER_R11"}` writes that entire string as code:
  core parseBody accepts any nonempty string; the logger only truncates it.
  This contradicts the advertised default structural-only, short enum-like
  code control. Required: withhold unknown free-text leaves by default and
  retain only vetted structural strings; validate diagnostic code shape
  conservatively rather than treating arbitrary body text as an enum.
  Preserve unknown-error event delivery without dumping its payload.
  Add default-off tests for arrays, unknown objects and invalid/free-text codes.

- **R11-03 [P1] — supported text credential forms leak.**
  `src/logging.ts:147-152,173-190,324`. In captured provider `message`,
  `{"x-api-key":"HEADER_SECRET_R11"}` and
  `{"set-cookie":"sid=COOKIE_SECRET_R11"}` persist both secrets.
  The JSON-secret expression only recognizes exact short key names; unlike
  structured-key normalization it does not cover these standard header names.
  In a non-JSON response body, `api_key="` followed by 100 repetitions of
  `LONG_CREDENTIAL_R11` and a closing quote persists the credential prefix:
  bodyDetails slices to 1024 before redaction, removing the closing quote
